# 资产与导入数据基线（设计稿）

未取得试点数据；不包含真实人员、设备、企业编码或现场验收结论。

## 编码及四种身份

- `asset_id` 为全局不可变 UUID；厂内 `asset_code` 唯一且不含可变位置含义，企业已有编码优先保留。
  编号纠错保留前后值，报废编号不无意复用；确切格式与保留期需试点负责人确认。
- `functional_position_id` 表示固定机位；更换设备关闭旧安装关系并开启新关系，不复用旧设备 ID。
- `location_id` 为工厂内位置树；位置改名不改变身份，历史记录保留发生时位置快照。
- `measurement_point_id` 为测点；可归属设备、机位或区域。外部编码通过带有效期、人工确认的映射关联。

生命周期为建档、待验收/安装、在用、停用/封存、调拨、报废；短期故障/维修另记运行可用状态。
二维码只携带可撤销的不透明标识，不包含凭据或工厂私密数据；扫码后仍校验身份与实体工厂。

## M1 导入协议

1. 先现场盘点并确定数据核对人、设备与组件边界，确认编码/分类/位置/负责人字典。
2. 模板至少含工厂、厂内编号、名称、分类、位置/机位、厂家型号、出厂号、生命周期、负责人引用、
   重要等级和来源行号；单位、日期、分类专属参数独立验证。
3. 校验未知字典、重复编码/出厂号候选、错误工厂/位置、缺责任人、扩展字段和附件类型；生成逐行错误清单。
4. 展示新增/疑似重复/变更差异，用户确认后才写入；原始文件指纹、操作者、核对结果与导入批次留痕。
5. 同一确认批次幂等；并发编号冲突拒绝并回滚本次确认，不能静默覆盖实物身份。部分成功策略需明确后再实现。
6. 报废、换码、更换设备和跨厂调拨均保留历史；对象文件采用受控存储，预览/下载另校验所有权。
