# M1-02 与 M1-03 后续接入任务

本文件为后续任务建议，不属于 M1-01 的开发或部署授权。当前只读基础仍需评审，
正式租户、员工、真实设备及生产数据库未接入。

## M1-02：真实身份与授权生命周期、只读渠道接入

- 核实飞书 H5/PC 官方身份交换协议与所需租户能力，完成服务端 `FeishuIdentityProvider`；
  覆盖错误租户/应用、凭证过期、重放、OAuth state/回跳绑定和身份解绑。
- 设计首位集团负责人受控初始化、账号绑定、三角色/工厂授权管理与审计；
  不从部门推导工厂，不公开匿名初始化端点，厂管理员单厂规则同时落实事务与数据库约束。
- 实现平台会话签发/轮换/退出、HttpOnly/Secure Cookie、CSRF/Origin 与期限策略；
  人员停用、离职/转岗、撤权事件经官方来源验证后落库，定期对账；测试旧会话立即失效。
- 根据豆包企业工作伙伴官方文档确认 `x-aily-jwt` 算法、可信密钥、issuer/audience、期限、
  租户/应用和身份来源，再实现 `DoubaoMcpIdentityProvider`；所有异常失败关闭。
- 按实际官方 MCP 传输协议包装两个只读工具，复用 `AssetQueries`；
  不直接查库，不增写工具，不以模型传入的工厂或用户代替授权。
- 加入过期/伪造/错误受众/密钥轮换/来源错误/跨厂搜索/直接 UUID/角色变更/身份解绑测试；
  在安全获准的沙箱中验证 H5 容器与豆包只读调用。没有证据的真实集成继续标记 UNVERIFIED。
- 工程门槛：迁移账号与最小权限运行账号分离、TLS/同源代理、日志脱敏与认证测试产物隔离、
  Python 完整依赖锁定、备份恢复演练。是否上线必须另行明确授权。

验收：PC/H5/豆包对同一身份得到一致的工厂范围；撤权、停用或解绑后各渠道均拒绝旧凭证；
无令牌/员工信息进入代码、日志或 artifact。独立 Draft PR，不自行 Ready/Merge/Deploy。

## M1-03：设备台账维护及数据准备

- 经需求确认后细分小 PR：基础设备写入/校验、编号变更及审计、版本并发与幂等；
  不把实时故障状态混入生命周期，不物理删除已有履历的资产。
- 落地位置树、功能机位、安装关系有效期；跨厂外键一致性、层级环与并发重叠检查。
  当前 `assets.location` 只作为描述兼容迁移，不能直接覆盖历史代替安装/调拨事件。
- 依据 [资产基线](../data/ASSET_BASELINE.md) 实现 Excel 校验与差异预览，获确认后才导入；
  重复编号、分类扩展与跨厂数据必须报明确错误。先用合成文件验证，不取得真实设备数据。
- 附件单独定义所属资源、工厂、对象存储授权、恶意文件/大小校验和短期下载链接；
  权限撤销后不得继续拿新链接，不能复用公共目录冒充授权。
- 二维码使用可撤销标识与受控深链，扫码后重新鉴权；相机/飞书 SDK 接入另行验收。
- 保留现有 Vue 模块布局，只把本轮禁用操作逐项接入真实服务；区分保存中、失败、冲突、
  权限拒绝与确实成功，不添加假保存提示。
- 按 V1.3 设计资产跨厂调拨、安装历史和独立复核；没有完整历史授权规则前不开放调拨。
- 扩展迁移、回滚、事务失败、重复提交、跨厂附件/导入、并发冲突及 PC/H5 回归测试。

验收：设备业务事实始终保存在独立运维数据库；写操作与审计同事务，后续通知采用 outbox。
本任务不包含巡检、维修、保养、库存、PLC/监控控制或正式豆包写工具。
监控映射只延续原有设计，真实连接需单独授权与接口核实。
