# M1-02 后续验证与豆包只读接入

本清单不授权部署、正式租户操作、真实员工采集或 MCP 发布。所有未实测外部能力继续标记 UNVERIFIED。

## 飞书真实沙箱验收（UNVERIFIED）

1. 由企业管理员核实自建应用 App ID/租户、最小身份权限、可见范围与固定 HTTPS 回调。
   App Secret 只通过受控环境注入，不能提供给前端、GitHub、截图或日志。
2. 在获准沙箱分别验证 PC、飞书 iOS/Android 顶层 H5 重定向、Cookie 与原目标回跳，
   核实是否免确认、是否受客户端版本/第三方 Cookie 限制；本轮不声称这些设备能力已验证。
3. 复核官方 v2/v3 token 与 PKCE 的最新兼容说明；迁移时重新验证正常/错误 challenge、
   code 过期/重放、错误应用/租户与拒绝授权，不静默降低 PKCE 或关闭 TLS。
4. 用已验证的待授权账号走受控首位集团负责人流程，再授权工程师/管理员，验证撤权和退出。
   纠错/解绑恢复需确认真实身份与授权，不按姓名、部门或手机号自动合并。

## 人员事件与运营门槛（UNVERIFIED）

- 在任何事件接入前核实官方人员停用/离职/变更事件类型、所需订阅及通讯录权限、
  回调签名/解密/时间窗、重放防护、挑战验证、事件来源和租户/应用绑定。
- 事件和定期对账共同处理重复、乱序、漏发与恢复；只更新同一内部账号及生命周期服务，
  不复制一套授权逻辑。审计和撤会话同事务，失败有可见补偿，不声称同步完成。
- 尚未取得权限期间继续人工受控停用，明确离职处理负责人；现有会话不会凭空感知飞书人员变化。
- 分离最小权限运行账号与迁移账号；落实入口限流、挑战/会话过期清理、可信同源代理/TLS、
  日志去查询串与凭据、审计保留/归档、依赖锁定及备份恢复演练。
- 生产数据的回退保留 schema 和审计，采用前向修复或经评审的恢复；不得为降级删除授权事实。

## 豆包 MCP 只读适配（UNVERIFIED）

- 先读豆包企业工作伙伴官方文档确认 x-aily-jwt 签名算法、可信密钥/JWKS、issuer/audience、
  exp/nbf/iat、身份来源、租户/应用范围、重放/请求绑定及密钥轮换；不编造官方参数或仅解析 payload。
- 经签名与期限验证后，以完整身份键映射同一个 users/external_identities，
  继续使用同一工厂授权及应用服务；账号停用和解绑必须失败关闭。
- 只封装现有 search_assets/get_asset_detail；禁止匿名公开监听、客户端自报 user_id、
  绕过 factory_id 校验、直接查库或返回未经授权附件。
- 测试密钥未知/轮换、算法混淆、过期/未生效/错误受众或来源、无本地授权、跨厂搜索/UUID、
  调厂/停用/撤权、身份解绑和并发；CI 始终使用隔离数据库与合成身份。
- 协议错误映射、结构化输出及 transport 独立于设备服务，保留现有 API/PC/H5 回归。
  任何写工具、正式账号接入或发布必须另行任务与审核。
