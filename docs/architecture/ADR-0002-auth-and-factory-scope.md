# ADR-0002：三种管理角色与工厂数据范围

状态：拟定（M0 待确认） | 日期：2026-11-01

## 决策

只定义三种正式管理角色：集团负责人、工程师、加工厂设备管理员。角色决定允许的动作，`user_factory_access` 决定工厂数据范围，任务指派和自身业务状态进一步限制操作。

- 集团负责人具有集团范围；跨厂的危险资产操作仍需业务审计与确认。
- 工程师仅访问被明确授权工厂，可能多厂。
- 加工厂设备管理员仅访问本厂。
- 普通报修和现场受限执行按“仅本人/仅被指派任务”特定能力实现，不增加管理角色。
- 工单实际维修人不得验收自己修的工单；如果唯一人员无法独立验收，则上报集团负责人或另一位授权工程师。
- 飞书身份只解决“是谁”，不授予工厂/管理角色。

## 实现要求

服务端每次基于实体工厂和操作者授权判断；禁止只靠前端路由控制。审计记录必须保存操作时的 actor_id、role、factory_id、resource_id、前后状态、时间、原因；离职后历史操作身份不删除。

## M0 策略审阅补充（2026-11-01）

工程师可多厂，厂管理员最多一厂；未知角色和可变授权集合在构造领域快照时拒绝。
验收示例新增必传的 `awaiting_verification` 条件，缺少实际维修人记录时同样拒绝；集团负责人无自验特权。
以上属于未接入 API 的纯策略，不能声称已启用认证、撤权或工单状态机。

兼容性：仅调整 M0 内部示例函数签名；无已发布业务 API、数据库或真实用户。
无迁移；回滚为撤销该初始化提交，禁止以移除约束作为未来线上兼容方案。
