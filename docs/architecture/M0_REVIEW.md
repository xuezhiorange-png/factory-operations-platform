## 原工程包缺口处理

1. 原 `Principal` 可携带未知角色/多厂管理员授权：增加构造约束和负测。
2. 原验收策略不含状态、允许缺失维修人证据：必传待验收条件并对空维修人拒绝，更新 ADR。
3. 缺 npm 锁文件：联网生成后改用 `npm ci`；不再保留未验证前端的旧结论。
4. 只有分层说明没有可检查的分层骨架：增加预留包和 AST 依赖守卫，不生成虚假的已实现业务模块。
5. 设计缺少接口目录、导入协议及回滚说明：补充 API / data / acceptance / operations 文档并纳入文档检查。

## UNVERIFIED 与后续工作

- GitHub 仓库可用性、建仓权限、远程 Actions、Draft PR 与分支保护以
  [本地验证记录](../delivery/LOCAL_VERIFICATION.md) 的实测为准；不得把 actionlint 当成远程 CI。
- 飞书租户应用权限/身份字段、登录/离职事件、相机/扫码、机器人投递均未访问或实测。
- 监控真实仓库/API/认证、事件 ID/游标、SSO/webhook、时区/断联语义和样本映射均未取得，不作存在性推断。
- 试点设备盘点/分类/编码、任务执行人、巡检表、工单状态迁移及安全确认必须现场评审。
- 数据库、事务回滚、并发、附件安全和撤权需要 M1/M3 集成测试，不能以纯函数测试代替。
- M1 才实现平台授权和台账；M3 才实现维修闭环；M5 才接入经确认的只读监控事件。
